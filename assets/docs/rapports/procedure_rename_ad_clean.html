1. Contexte Opérationnel & Principes d'Architecture Hybride Architecture

Lorsqu'un collaborateur modifie son état civil (mariage, changement de nom) ou que la convention de nommage interne impose une refonte de son identifiant, l'équipe d'administration système doit adapter l'ensemble de ses identités numériques sans rupture de service.

Dans une architecture d'entreprise hybride synchronisée avec Microsoft Entra Connect (ex-Azure AD Connect), l'Active Directory local est la Source Unique de Vérité (Source of Authority). Toute modification effectuée directement sur le portail cloud est immédiatement écrasée au cycle de synchronisation suivant.

Règle d'or : La totalité des modifications d'identité, d'identifiant d'ouverture de session et d'alias doit être opérée en premier lieu sur le contrôleur de domaine On-Premises avant propagation vers le cloud.
2. Modification de l'Identité sur le Contrôleur de Domaine (Interface Graphique) Étape 01

Pour une modification unitaire assistée par la console MMC Utilisateurs et ordinateurs Active Directory (ADUC) :

  • Ouvrir la console dsa.msc avec un compte membre du groupe Administrateurs du Domaine.
  • Localiser le compte dans l'Unité d'Organisation (OU) cible, faire un clic droit et sélectionner Renommer.
  • Renseigner les nouvelles valeurs d'état civil : Prénom, Nom, Nom complet, et le nouvel UPN (User Principal Name).
  • Ouvrir les Propriétés du compte :
    • Onglet Général : mettre à jour le champ Adresse de messagerie (ex: j.martin@eodd.fr).
    • Onglet Compte : actualiser le Nom d'ouverture de session de l'utilisateur (j.martin) et le nom pré-Windows 2000 (EODD\j.martin).

3. Gestion des Alias de Messagerie via l'Attribut proxyAddresses Étape 02

Afin que le collaborateur continue de recevoir les messages adressés à son ancien patronyme (historique d'échanges avec des clients et correspondants externes), il est impératif de configurer les alias de messagerie. L'attribut proxyAddresses n'étant pas accessible simplement via les onglets standards, cette opération est réalisée en PowerShell.

Spécification RFC / Microsoft Exchange : Le préfixe SMTP: (majuscules) définit l'adresse d'envoi et de réponse principale (Primary Reply-To). Le préfixe smtp: (minuscules) définit les alias de réception secondaires.
PowerShell · Contrôleur de Domaine Configuration de l'attribut proxyAddresses
$NouveauLogin = "j.martin"
$NouvelEmail = "j.martin@eodd.fr"
$AncienEmail = "j.dupont@eodd.fr"

# Affectation de l'adresse principale et préservation de l'ancienne en alias
Set-ADUser -Identity $NouveauLogin -Replace @{proxyAddresses = "SMTP:$NouvelEmail", "smtp:$AncienEmail"}
4. Procédure Alternative : Automatisation Complète 100% Scriptée Industrialisation

Pour accélérer le traitement et éliminer les erreurs de saisie manuelle, l'intégralité des opérations (modification des attributs, renommage du conteneur CN et configuration des alias) peut être exécutée d'une seule traite via ce script d'administration :

PowerShell · Script Complet de Traitement Automatisation L2/L3
# Variables d'entrée du collaborateur
$AncienLogin = "j.dupont"
$NouveauLogin = "j.martin"
$NouveauPrenom = "Jeanne"
$NouveauNom = "MARTIN"
$NouvelEmail = "j.martin@eodd.fr"
$AncienEmail = "$AncienLogin@eodd.fr"

# 1. Mise à jour simultanée des attributs du compte
Set-ADUser -Identity $AncienLogin `
-GivenName $NouveauPrenom `
-Surname $NouveauNom `
-DisplayName "$NouveauPrenom $NouveauNom" `
-UserPrincipalName $NouvelEmail `
-EmailAddress $NouvelEmail `
-SamAccountName $NouveauLogin

# 2. Renommage de l'objet dans le conteneur Active Directory (Common Name)
$User = Get-ADUser -Identity $NouveauLogin
Rename-ADObject -Identity $User.DistinguishedName -NewName "$NouveauPrenom $NouveauNom"

# 3. Écriture des alias de messagerie SMTP principal et secondaire
Set-ADUser -Identity $NouveauLogin -Replace @{proxyAddresses = "SMTP:$NouvelEmail", "smtp:$AncienEmail"}
5. Forçage Immédiat de la Synchronisation Hybride (Microsoft Entra Connect) Étape 03

Le cycle automatique de synchronisation Microsoft Entra Connect s'exécute toutes les 30 minutes. Afin d'appliquer immédiatement les modifications sur le tenant Microsoft 365 sans délai de latence :

PowerShell · Serveur Entra Connect Synchronisation Delta
PS C:\> Start-ADSyncSyncCycle -PolicyType Delta
Synchronisation Delta : Seuls les objets et attributs modifiés depuis le dernier cycle sont analysés et poussés vers le répertoire Entra ID, réduisant le temps de réplication cloud à moins de 60 secondes.

7. Résolution des Caches Locaux & Post-Traitement (Microsoft Teams & Outlook) Support

Certaines applications de l'écosystème Microsoft 365 utilisent un cache local persistant pouvant retarder l'affichage du nouveau nom chez les collègues :

  • Comportement Microsoft Teams : Le cache local du client lourd peut conserver l'ancienne identité pendant 24h à 48h. Pour vérifier la réalité de la modification, consulter Teams Web (teams.microsoft.com) où l'actualisation est instantanée.
  • Forçage immédiat sur poste client : Demander à l'utilisateur ou à ses collaborateurs proches de se déconnecter de Teams (Profil > Se déconnecter) puis de se reconnecter. Si nécessaire, purger le dossier %appdata%\Microsoft\Teams.
  • Client lourd Outlook : Redémarrer Outlook pour reconstruire le Carnet d'Adresses Hors Connexion (OAB - Offline Address Book).
Synthèse d'intervention : Changement d'identité complet et transparent, conservation de l'antériorité des accès et de la réception des courriels professionnels, conformité avec l'annuaire d'entreprise EODD.
